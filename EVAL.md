## 1. Planted-claim recall — `eval/results/run_20261024T122104Z.json`

60 deliberately wrong claims (15 per type), each paired with a short passage, pushed through the real Verifier (`verify_all`): 57 of 60 were rejected.

| Type | Rejected |
|---|---|
| wrong_number | 15/15 (1.00) |
| wrong_entity | 15/15 (1.00) |
| contradiction | 15/15 (1.00) |
| unsupported_extrapolation | 12/15 (0.80) |
| **Overall** | **57/60 (0.95)** |

Two things this does *not* show, stated plainly:
- **All 57 rejections came from the LLM's entailment judgment** (`stage_failed=entailment`). None was caught by the code-side span-exists or numeric checks. On these fixtures the model said "unsupported", so the code layers were never the deciding vote. They are a backstop against a model that lies about entailment, but this test does not exercise that case.
- The passages are short authored fixtures, so this is a regression test of the Verifier, not a claim about live-web accuracy.

The 3 misses are in the failure gallery (#5–#7).

## 2. Independent re-grade of final reports — `eval/results/grade_existing_20261024T125734Z.json`

For each run's final report, every *cited* sentence was re-judged by the `grader` role (`anthropic/claude-sonnet-5`) against the stored passage behind its citation. The grader shares no model with the Verifier or Auditor (enforced by `tests/unit/test_model_roles.py`) and sees none of their verdicts. "Strict" counts only `supported`; "lenient" also counts `partial`. There were 0 grader errors.

| Group | Runs | Cited sentences | Strict | Lenient | Claims passing verification |
|---|---|---|---|---|---|
| **Corrected model config** (Verifier = haiku-4.5 only) | 7 | 124 | **100/124 = 0.806** | 122/124 = 0.984 | 369/393 = 0.939 |
| Earlier config (Verifier mostly `gpt-4o`, same model as Auditor) | 3 | 92 | 75/92 = 0.815 | 87/92 = 0.946 | 256/273 = 0.938 |
| All | 10 | 216 | 175/216 = 0.810 | 209/216 = 0.968 | 625/666 = 0.938 |

Reading it honestly:
- About 81% of cited sentences are fully supported by their cited passage by a strict, independent standard, and about 97% are at least partly supported. 7 of 216 (3.2%) were judged unsupported (gallery #1–#4).
- The corrected-config group is not measurably better than the old one (0.806 vs 0.815 strict). The sample is small and has no confidence interval, so this does not show the model fix improved quality. It shows that the same-model problem is now closed in config.
- Four of the seven corrected-config runs are the first four questions of the sweep (`fin-01`, `fin-02`, `health-01`, `health-02`). The other three are earlier interactive runs. Of the four sweep runs, two stopped with `no_new_evidence` after one iteration, which is likely Firecrawl rate-limiting starving the re-research step, so they are weaker evidence for loop behaviour.
- "Claims passing verification" is the Verifier's own pass rate, not independent accuracy.

## Failure gallery (real failures)

1. **Cited passage doesn't say it (EV, old config).** *"Battery factories in Europe and the United States depend heavily on imports from China and Korea…"* The cited passage only says the midstream supply chain is "in stark need of diversification". The Auditor wrote that the evidence "does not specifically mention dependency on imports" and **still passed it**. Lesson: the Auditor treats `partial` as a pass.
2. **Same fact, reworded (EV, old config).** *"…heavily reliant on imports from China for most of their components, highlighting a geopolitical vulnerability."* The same unsupported leap, restated; the Auditor's reason again says the evidence "does not specifically state" it.
3. **Same failure on the corrected config (EV, `27aba3b6`).** *"…heavily dependent on imports… primarily from China, which poses a policy risk due to potential trade restrictions or tariffs."* The Auditor admits the passage only "implies dependency". So the model swap did not fix this class of error.
4. **Auditor says supported, grader disagrees.** *"Agentic RAG incorporates real-time web searches and query refinement for enhanced retrieval precision."* The Auditor says the evidence "directly states" it; the independent grader finds the passage (a list of agent roles and features) does not. This is a case where two same-pipeline judgments agreed and a third model did not.
5. **Planted `ue-01` accepted as `partial`.** Passage: *"Sales in the **Northeast region** grew 14%…"*; planted claim: *"The company's **overall** sales grew 14%…"*. The Verifier let the scope inflation through as partial.
6. **Planted `ue-03` accepted as `partial`.** Passage: *"**One major retailer** reported a slowdown…"*; claim: *"Consumer spending **across the entire economy** slowed…"*.
7. **Planted `ue-04` accepted as `partial`.** Passage: *"…reduced emissions by 15% **at the single facility** where it was tested"*; claim: *"The program will reduce **national** emissions by 15% once rolled out."*

**What the gallery says about the design:** the weakest point is the `partial` verdict. It passes verification, so over-generalization (a regional fact stated as national, one retailer stated as the economy) and reasonable-sounding inference both slip through, and the Auditor repeats the same leniency. The strict independent grader is what exposes it. A concrete next fix is to require `supported` for anything with a scope-widening word (overall, entire, national, most) or to render `partial` claims with a visible qualifier. That was not done in this round.

## What is built (and unit-tested without credits)

| Component | What it does | Verified by |
|---|---|---|
| `eval/questions.yaml` | 30 questions across 6 domains with rubrics written before any run, plus 5 false-premise questions | Loaded by `run_eval.py` |
| `eval/planted_claims.yaml` | 60 planted bad claims, 15 per type | `tests/integration/test_eval_planted_claims.py`; run for real above |
| `eval/injection_pages/` | 3 prompt-injection HTML fixtures | **Not yet run** through the pipeline |
| `eval/run_eval.py` | Planted-claim recall, gold-label agreement, the full-pipeline sweep with independent grading, rubric coverage and abstention; resumable and written incrementally | `tests/unit/test_eval_metrics.py`, `test_eval_grader.py` |
| `eval/grade_runs.py` | Independent re-grade of runs already stored in the DB (Mesh only) | Run for real above |
| `eval/baseline.py` | Single-prompt "answer with citations" comparator, scored with the Auditor's standard | `tests/integration/test_baseline_scoring.py`; not run live (see scope table) |
| `eval/label.py` | CLI for collecting human gold labels from a real run | Needs a human |
| `eval/report.py` | Renders a results JSON as the metric table with bootstrap 95% CIs | `tests/unit/test_eval_metrics.py` |

Bugs the live evaluation found in our own code, all fixed with tests: `evaluate_question` crashed on a missing `claim_ids` key; Firecrawl rate-limit errors were treated as ordinary failures (now retried, honouring `retry after`, with a process-wide concurrency cap — `tests/unit/test_firecrawl_rate_limit.py`).
